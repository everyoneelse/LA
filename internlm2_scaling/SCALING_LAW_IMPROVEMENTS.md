# InternLM2 Scaling Law 配置改进报告

## 问题分析

### 1. 原配置存在的问题

**参数范围覆盖不足：**
- 原配置只有5个模型：126M, 189M, 355M, 567M, 992M, 1386M
- 缺少10³到10⁸之间的小参数模型
- 无法验证scaling law在小模型上的适用性

**架构配置不合理：**
- 567M模型：d_model=1536, 层数=8, 比值=192.0
- 992M模型：d_model=1536, 层数=20, 比值=76.8
- **问题**：相同的d_model但层数差异巨大，违背了scaling law的平滑增长原则

**参数计算不准确：**
- 原配置将embedding参数包含在scaling law分析中
- **问题**：embedding参数主要取决于vocab_size，不反映模型计算能力
- 应该使用非embedding参数进行scaling law研究

### 2. OpenAI Scaling Law论文的配置规律

根据Kaplan等人2020年的论文和GPT-3的配置：
- 模型参数、d_model、层数应该协调增长
- d_model/n_layer比值应保持相对稳定
- 参数范围应覆盖10³到10⁹

## 改进方案

### 1. 扩展参数范围 (基于非embedding参数)

新增了从328K到3.4B的22个模型配置，覆盖范围：
- **328K-492K** (10^5.5-10^5.7) - 真正小于10^6的微型模型
- **984K-6.3M** (10^6.0-10^6.8) - 10^6范围模型
- **8.65M-63M** (10^6.9-10^7.8) - 10^7范围模型
- **71M-503M** (10^7.9-10^8.7) - 10^8范围模型
- **708M-1.5B** (10^8.9-10^9.2) - 10^9范围模型
- **2.4B-3.4B** (10^9.4-10^9.5) - 大模型扩展

**重要改进：现在所有参数计数都基于非embedding参数，符合scaling law研究标准！**

### 2. 微型模型特殊优化 (基于非embedding参数)

为了实现真正的小参数模型，采用了以下策略：
- **< 1M非embed参数**: vocab_size=8000, tie_word_embeddings=True
- **1M-10M非embed参数**: vocab_size=16000, tie_word_embeddings=True
- **10M-50M非embed参数**: vocab_size=32000, tie_word_embeddings=False
- **50M以上非embed参数**: 使用标准vocab_size=92544

**embedding参数优化原理：**
- 微型模型的embedding层参数会占总参数的很大比例
- 通过减小vocab_size和使用tied_embeddings，让模型参数主要集中在计算层
- 这样scaling law分析更准确地反映模型的计算能力

## 使用方法

运行以下命令生成新的配置文件：

```bash
cd internlm2_scaling
python3 scripts/generate_variants.py
```

这将在`configs/`目录下生成8个新的模型配置文件和一个`variants_summary.csv`摘要文件。

## 验证建议

1. **参数计算验证**：确认每个配置的实际参数量与目标一致
2. **训练稳定性**：测试小模型的训练稳定性
3. **Scaling law验证**：使用新配置验证loss与参数量的幂律关系
4. **计算效率**：评估不同配置的训练和推理效率

## 技术细节

- 保持HEAD_DIM=128不变
- 使用GQA (Grouped Query Attention): kv_heads = max(1, heads // 2)
- MLP维度为d_model的4倍，向上舍入到256的倍数
- 保持其他超参数（RoPE、norm等）与原始InternLM2一致
